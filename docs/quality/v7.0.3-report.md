# Kinex 7.0.3 engineering report

## Executive summary

Implemented the local security, reliability, and compatibility overhaul while preserving the existing UI and browser model. At the initial implementation handoff, no commit, push, PR, release, deployment, or repository secret change had been made. The user subsequently authorized committing and pushing v7.0.3 source to origin/main. No release or tag publication is part of that authorization. Development and runtime fixtures use temporary profiles. Downloads in the main integration fixture now use its temporary directory.

Release decision: **NOT READY for public release**. Unsigned arm64 packaging and startup pass. Developer ID signing, notarization, signed update installation, authenticated provider workflows, hardware consent, and protected playback remain unverified. This is suitable for further local qualification, not a claim of complete everyday-browser compatibility.

## Implementation and security

- Runtime upgraded from installed Electron 36.9.5, declared ^36.2.0, to pinned Electron 45.3.3, Chromium 156.0.8078.100, embedded Node 24.22.3. macOS 13 is the new minimum. Vite 8, Vitest 5, electron-builder 26.18, Node definitions, and patched minimatch are integrated. The audit changed from 11 advisories, including two critical and two high, to zero.
- Every IPC endpoint requires registered role, exact internal document, main-frame identity, and typed payload validation. Empty sender allowlists fail closed. Websites have no privileged preload, Node, worker Node, subframe Node, webviews, or insecure mixed content.
- Permission decisions include partition, origin, and capability. Microphone and camera use separate grants. Unscoped legacy grants require reconsent. Unknown sensitive capabilities deny, stale dialogs cannot grant after navigation or crashes, and insecure LAN hosts do not receive loopback trust.
- TLS approvals include session, origin, fingerprint, and error. HTTP fallback is session-scoped and requires explicit consent. Same-origin blob previews use sandboxed popups. Little Kinex recreates its browsing context after a profile change.
- Internal protocol responses use nonce-authorized scripts and default-deny CSP. Reader scripts are denied. Existing inline theme styles remain. External website CSP is unchanged.
- Persistence validates records and splits, retains damaged originals with private backups, and prevents old async writes from replacing the latest shutdown snapshot. Valid tabs, pinning, order, splits, profiles, and empty collections are preserved.
- Downloads handle more than 99 filename collisions, dot names, symlinks and simultaneous regular/private reservations. Private popups are destroyed before independent storage/cache/auth/connection cleanup.
- Shields catches native initialization failures, validates compiled-cache integrity, preserves concurrent settings, applies top-page exceptions inside third-party frames, handles update disk failures and HTTPS redirects, cancels disposed work, filters WebSockets, and clears cosmetic tracking. Cold compilation runs in a worker while initial requests wait. Packaged workers use a pure bundled filter path and do not import Electron app APIs.
- Updater file serving rejects malformed encodings, traversal, symlinks and unrelated files, streams asynchronously, handles disposal during binding, and keeps update listeners alive across macOS window close. Async clipboard migration awaits or handles rejected writes rather than reporting false success.
- CI uses pinned action SHAs, read-only verification permissions, Node 24, separate pure/native checks, auditing, real Electron and packaged checks. The release workflow requires signing credentials and notarization before publication. Hosted workflow execution was not triggered.

The Model the Domain principle kept profile ownership in the existing permission key. Prove It Works required actual Electron sessions, renderer termination, and packaged native execution rather than compilation alone. Independent inherited-model reviewers found additional updater and entitlement issues that were corrected; cross-family review tooling was unavailable.

## Migration details

Reviewed official Electron breaking changes from 37 through 45. Removed obsolete WebSQL storage cleanup. The sandbox preload uses only supported Electron APIs and does not depend on removed Node shims. Clipboard writes now use the asynchronous API. Navigation already uses navigationHistory. Display capture uses the macOS system picker where available, with a denied fallback. Camera, microphone and location usage descriptions and targeted hardened-runtime entitlements are configured.

Sources: [Electron 45.3.3](https://releases.electronjs.org/release/v45.3.3), [breaking changes](https://www.electronjs.org/docs/latest/breaking-changes), and [support policy](https://www.electronjs.org/docs/latest/tutorial/electron-timelines).

## Performance and compatibility

[Performance results](performance-v7.0.3.md) record all samples and limitations. Five alternating Shields runs reduced median maximum Main timer gap from about 84.94 ms to 8.72 ms. Protection readiness changed from 84.87 ms to 106.03 ms. Overall app startup is inconclusive. Observed 50-tab RSS rose from 4898.9 MB to 5319.5 MB after the Chromium upgrade. Memory Saver reduced a separate 50-tab run to 896.7 MB.

The [compatibility matrix](compatibility-matrix.md) includes all twelve requested sites. Google Search was blocked by anti-bot checks. Login and marketing pages are limited public scenarios. The final Figma readiness probe failed despite a rendered page and an earlier public pass; it remains recorded. YouTube video clock progression passed. A temporary-profile Widevine request returned NotSupportedError. Netflix protected playback is not supported by this evidence.

## Remaining issues

- P0: No critical regression identified in the inspected and executed scope. This is not a security certification.
- P1: Signed distribution, notarization, Gatekeeper acceptance and signed update installation are unqualified release gates.
- P2: Authenticated OAuth/MFA/editor/collaboration workflows and physical camera/microphone/location/screen-sharing consent are blocked by account and signed-build prerequisites. DRM requires legitimate licensing and provider qualification. Figma final readiness remains unresolved.
- P2: Chromium 156 has higher observed RSS. More repeated measurements are needed before attributing or optimizing the increase. Filter-setting and some update rebuilds remain synchronous.
- P3: Native focus assertions previously failed intermittently. Synchronized tests pass, but longer interactive qualification remains valuable. Transitive tooling deprecations, full Intel/macOS 13 coverage, GPU-crash recovery, and native-menu traversal remain unqualified. The existing release-local helper still deserves separate version/lockfile lifecycle qualification; use npm version with --no-git-tag-version for controlled version changes.

## Significant files
