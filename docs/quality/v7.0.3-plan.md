## Baseline and architecture

The clean checkout is 7.0.2 with Electron 36.9.5 installed, declared ^36.2.0. Main uses BrowserWindow plus sandboxed WebContentsView tabs and lazy overlay. A narrow shell preload exposes five named IPC channels. Profile partitions own Chromium storage. Spaces can intentionally share a profile. Private windows use nonpersistent partitions. One native Shields engine serves session request interceptors. Persistence debounces async writes and flushes synchronously at shutdown.

Observed baseline: typecheck passes, 43 tests pass across 9 files, production build passes. Electron integration passes 15 grouped checks. Initial sandbox GUI/network failures were environment restrictions, then rerun outside sandbox. Baseline npm audit and runtime/performance output are retained under artifacts/v7.0.3 and /private/tmp/kinex-baseline-* while final evidence is assembled. Historical benchmark reports are historical observations, not current release gates.

## Data contracts and design choices

Permission decisions become keyed by partition, origin, and capability in the existing store. Unscoped legacy grants require new consent. Persistence keeps synchronous shutdown semantics with generation-tagged temporary writes rather than introducing an async shutdown framework. Shields keeps its single coalesced updater and merges downloaded metadata into current settings instead of cancelling on every unrelated setting change. These choices preserve callers and keep checks at trust boundaries.
